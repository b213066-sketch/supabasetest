# 아키텍처

최종 갱신: 2026-10-28
상태: 구현 전 설계 초안. 아래 기술과 스키마는 아직 설치·적용되지 않았다.

## 목표와 범위
방문자가 사진 또는 직접 그린 그림 한 장과 선택 메시지를 남기고, 포스트잇 보드와 상세 댓글로 소통하는 한국어 반응형 웹 앱을 만든다.
MVP는 작성 페이지, 보드 페이지, 상세 모달, 실시간 새 방명록·댓글·댓글 수 갱신을 포함한다.
회원가입 화면 없이 Supabase 익명 인증으로 내부 작성자를 식별한다. 기존 그림의 공동 편집, 방명록·댓글 수정 및 삭제 UI는 MVP 범위 밖이다.

## 현재 저장소
- GitHub: https://github.com/b213066-sketch/supabasetest.git
- 이 문서의 상위 디렉터리가 실제 Git 저장소 루트다. 현재 작업 공간에는 같은 이름의 상위 폴더와 중첩되어 있다.
- 최초 확인 시 저장소에는 앱 코드, 패키지 설정, 커밋이 없었다.
- 앱은 이 저장소 루트에 구현한다. 상위 작업 공간의 별도 Git 저장소와 혼동하지 않는다.

## 기술 선택안
- 프런트엔드: React + TypeScript + Vite, React Router로 `/` 작성 화면과 `/board` 보드 화면 구성.
- 스타일: CSS와 CSS 변수로 파스텔 테마, 종이 질감, 반응형 배치 구현.
- 그림 입력: 브라우저 Canvas와 Pointer Events. 펜 색·굵기, 지우개, 실행 취소, 전체 지우기 지원.
- 백엔드: Supabase Auth, Postgres Database, Storage, Realtime.
- 정적 프런트엔드 중심으로 시작한다. 비밀키나 권한 작업이 필요한 경우에만 서버 기능을 추가한다.
- 실제 패키지 버전과 API는 구현 시 최신 공식 문서를 확인하고 확정한다.

## 화면과 상태
### 작성 `/`
- 닉네임, 선택 메시지, 사진/그림 모드, 포스트잇 색상을 입력한다.
- 사진은 한 장 미리보기·제거·교체를 지원한다. 그림은 비어 있는지 검사한다.
- 모드 전환으로 내용이 사라질 경우 안내한다. 터치 그리기 영역에서 스크롤 충돌을 막는다.
- 제출 중 중복 요청을 막고 진행 상태를 표시한다. 실패 시 입력을 유지하고 성공 시 보드로 이동한다.

### 보드 `/board`
- 이미지, 메시지 요약, 닉네임, 작성 시간, 댓글 수를 카드에 표시한다.
- 카드는 읽기 쉬운 격자로 배치하고 약간의 회전·그림자를 적용하되 내용을 겹치지 않는다.
- 최신순 커서 페이지네이션과 더 불러오기를 사용한다. 동일 시각 정렬은 ID로 결정한다.
- 빈 상태, 로딩, 오류, 재시도와 작성 화면 이동 버튼을 제공한다.

### 상세 모달
- 이미지와 전체 메시지, 작성자, 오래된 순 댓글을 표시한다.
- 닉네임·내용으로 댓글을 작성한다. 실패 시 입력 유지, 빈 값·중복 제출 방지를 적용한다.
- 모바일 화면에 맞춰 표시하며 닫기 버튼·바깥 클릭·Escape, 포커스 가두기와 복귀, 접근성 이름을 지원한다.

## 데이터 모델 초안
- `guestbook_entries`: UUID 기본 키, `author_id`(인증 사용자), 닉네임, 선택 메시지, `image_path`, `image_kind`(photo/drawing), 허용된 배경색, 서버 작성 시간.
- `comments`: UUID 기본 키, 방명록 외래 키 `entry_id`, `author_id`, 닉네임, 내용, 서버 작성 시간.
- 이미지 원본은 Storage에 저장하고 DB에는 파일 경로를 기록한다.
- 댓글 목록은 `(entry_id, created_at, id)`, 보드는 `(created_at, id)` 조회에 맞는 인덱스를 검토한다.
- 댓글 수는 DB 기준 집계로 조회하고 실시간 이벤트 이후 해당 방명록 수를 재조회한다. 이벤트마다 로컬 숫자만 증가시켜 누적 오차를 만들지 않는다.
- 중복 재시도 방지를 위해 제출 시 생성한 UUID를 재사용하고 이미 저장된 동일 ID는 결과 조회로 확인한다.
- 길이·형식 제한은 UI와 DB 제약에 일관되게 반영한다.

## 이미지 저장과 실패 복구
- 새 파일 경로는 사용자 ID와 방명록 UUID 기반으로 생성하고 기존 파일을 덮어쓰지 않는다.
- 익명 세션 확인 → 입력 검증 → 파일 업로드 → 방명록 저장 → 보드 이동 순서다.
- DB 저장 실패가 확정되면 업로드한 파일을 정리한다. 응답 유실로 성공 여부가 불명확하면 방명록 ID로 먼저 저장 여부를 확인한다.
- 정리 실패는 기록하고 재시도 가능한 절차를 설계한다. 브라우저 종료 후 남은 고아 파일의 주기적 정리는 별도 운영 작업으로 남긴다.

## 실시간 동기화
- 보드에서 새 방명록 및 댓글 수 갱신용 댓글 이벤트를 구독한다.
- 상세 모달에서는 해당 방명록의 새 댓글만 구독하고 닫을 때 해제한다. 보드 구독은 페이지 이탈 시 해제한다.
- 구독 연결 후 조회하고 이벤트를 병합해 최초 조회와 구독 사이의 누락을 방지한다.
- 조회 결과·저장 응답·이벤트를 UUID 기준으로 병합하고 결정적인 정렬을 유지한다.
- 재연결과 화면 복귀 시 표시 중인 목록·댓글 수를 다시 조회해 누락을 복구한다.
- 목록 더 불러오기와 실시간 삽입이 겹쳐도 중복이나 페이지 커서 손상이 없어야 한다.

## 권한과 보안
- 미인증 사용자도 공개 방명록·댓글을 읽는다. 작성에는 익명 인증 세션이 필요하다.
- 공개 스키마 테이블에 RLS를 적용하고 필요한 테이블 권한도 명시적으로 관리한다.
- INSERT는 `author_id = auth.uid()`를 강제한다. 닉네임은 표시용이며 권한 판단에 사용하지 않는다.
- MVP에서 방명록·댓글 UPDATE/DELETE는 허용하지 않는다.
- 이미지는 공개 열람 가능하다는 제품 정책 아래 Storage 공개 읽기를 구성하고 업로드는 본인 경로로 제한한다. 실패 업로드 정리 권한도 본인 파일로 제한한다.
- 파일 MIME·크기·이미지 해석 가능 여부를 검증하고 Storage의 제한도 설정한다. 사용자 입력을 HTML로 실행하지 않는다.
- 프런트엔드는 공개용 프로젝트 URL과 publishable 키만 사용한다. service_role/secret 키는 노출하지 않는다.
- 익명 세션은 브라우저마다 다르므로 여러 브라우저의 소유권이 같다고 가정하지 않는다.

## 구현 시 확정할 기본값
- 제안: 닉네임 1~20자, 메시지 최대 500자, 댓글 1~500자, 사진 JPEG/PNG/WebP 최대 5MB, 그림 PNG, 목록 20개 단위.
- 위 값은 요구사항의 확정값이 아니다. 구현 시 확정하고 UI·DB·Storage 검증을 맞춘다.
- Supabase 프로젝트 연결, 익명 인증 활성화, 공개 이미지 정책, Realtime publication, 배포 대상은 아직 확인되지 않았다.
